Method & limits

Evidence, not a verdict.

TwinShield compares access-point metadata with an owner-approved baseline. Its rules can find differences. They cannot establish who is operating a radio.

Names & addresses
An unfamiliar radio using an approved name adds 45 points. A name one small edit from an approved name adds 30.
Advertised security
Weaker security adds evidence. A downgrade on an approved radio adds 50 points; a new radio with weaker security adds 35.
Repeated sightings
A score of at least 60 needs two sightings to be labelled strong suspicious evidence. One sighting is capped at Review.
Weak signals
Channel, band and signal changes add smaller amounts. Walls, people and normal maintenance can explain them.
The blind spot

A copied radio address with matching security and a believable signal can look genuine. This is not a vulnerability audit, intrusion prevention system or promise of safe Wi-Fi.

Reads network names, radio addresses, channel, signal and advertised security. It does not capture traffic, collect credentials or disconnect anyone. Local records stay in ~/.twinshield.

From fixture to field

Bring your own baseline.

The website is a labelled example. Real scanning runs on your laptop, with Python 3.8 or newer and no Python packages to install.

  1. Get the source

    Clone or download the repository, then open its folder in a terminal.

  2. Start the local review desk 
    git clone https://github.com/Aditya2375/twinshield
cd twinshield
python3 -m twinshield serve
  3. Approve what you manage

    Open http://127.0.0.1:8787, wait for two completed scans, then select networks you own or are authorised to manage. Every later scan is compared with that baseline.

Linux or Windows for live scanning

Linux needs NetworkManager (nmcli); Windows uses netsh. Recent macOS versions lack the required built-in scanner. Use python3 -m twinshield serve --replay for a local test fixture instead.
